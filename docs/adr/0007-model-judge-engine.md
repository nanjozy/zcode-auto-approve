# ADR-0007：判定引擎从纯规则切换为模型判定

- 状态：Accepted（用户两轮访谈确认，2026-09-15）
- 日期：2026-09-15
- 取代：ADR-0003（白名单放行策略）与 ADR-0006（复合命令逐段分析），二者要点已并入文末「历史决策」小节；黑名单与 riskLevel 护栏以安全网形式保留（见 ADR-0008）

## 背景

M2 的纯规则判定覆盖面受结构匹配所限：`cd x && npm test`、`timeout 30 npm test`、`tar czf …` 等语义上安全的命令无法放行，弹窗仍然频繁。用户明确要求把自动审批改为**调用模型进行审批**。设计访谈（两轮，共 8 个决策）确认了以下选择，其中两项否决了我的推荐方案：

1. 调用通道：**复用 ZCode provider 配置**（`~/.zcode/v2/config.json` 第一个 enabled 且带密钥的 provider，env `ZAA_BASE_URL`/`ZAA_API_KEY`/`ZAA_MODEL` 可覆盖）。事实基础：本机无 headless zcode CLI；BigModel coding plan 提供 Anthropic messages 兼容端点。
2. 架构：**纯模型判定**（否决了推荐的"规则快路径 + 模型补位"混合方案）——模型是唯一判断者，规则不再作为前置快路径。
3. 模型与超时：GLM-5.3-Flash；单次 15s、总预算 25s；hook 注册超时提到 30s。
4. 缓存：文件缓存，TTL 24h、上限 500 条。
5. 故障降级：**重试 3 次（共 4 次尝试）后转人工审批**（否决了推荐的"降级到规则引擎"）。

## 决策

Bash 命令的审批判定由 LLM 完成：命令以 JSON 数据嵌入 prompt（注入防护见 ADR-0008），temperature 0，输出严格 JSON `{decision: approve|ask, reason}`；approve/ask 都入 24h 文件缓存；重试耗尽、网络失败、provider 缺失一律直通人工。模型之上保留最小安全网与机械层（ADR-0008）。

## 备选方案（含被否决理由）

- **混合架构（推荐，被否决）**：规则硬护栏前置 + 模型只判 no-match 区。用户选择纯模型，接受模型为主判断者；安全底线由 ADR-0008 的后置安全网承担，混合方案的增量收益有限。
- **故障降级到规则引擎（推荐，被否决）**：用户选择"重试 3 次后转人工"——语义更纯粹（纯模型就纯模型），代价是 API 故障天可用性归零（退化为全弹窗，不降安全）。
- **本地小模型**：本机无 Ollama 等运行时，未纳入。

## 后果

- 正面：语义级覆盖——结构白名单外的常规命令（cd/timeout/tar/chmod/npx 等）可放行；判定理由可解释（入审计）；`deny.patterns` 收紧立即对缓存生效。
- 负面：每条新命令一次模型调用（实测 Flash p50 ≈ 3s、慢例 ≈ 13.5s，接近 15s 单次预算——预算是纯配置，可调）；费用走用户 coding plan 配额；模型抖动可能造成同命令判定漂移（缓存缓解）。
- M2 资产处置：白名单/argGuards/目标守卫/复合命令逐段分析/重定向护栏**退出判定路径**；分词器保留（安全网分段）；deny 正则降级为安全网（ADR-0008）；rules.json 升 v2，v1 文件被 loadRules 拒绝。

## 历史决策（M2，原文已并入）

v0.2（M2）的两份判定机制 ADR 随本决策退役，原文件已删除，要点压缩如下；完整原文见 git 历史（`a56e2c0` 初稿、`d04b2fd` 修订）。

- **ADR-0003：放行策略——分级白名单 + 黑名单优先 + riskLevel 护栏**（Superseded，2026-09-15）。M2 采用谱系中的中等档：deny 正则与高危工具/MCP 黑名单永远优先；riskLevel 作独立上限护栏（moderate 档上限 medium）；`readonly`/`safework` 白名单组按 profile 开合；Write/Edit 仅限 workspace 内。理由：判定规则全部版本控制在本仓库，可审计可回滚，不把安全判断整体外包给 ZCode 的 riskLevel 分类器。M2 实施修订收紧了草案的任意代码执行通道：新增 `argGuards`（拦 `node -e`/`find -exec` 等）、`npx`/`npm exec` 移出白名单、`cp`/`mv` 内置目标路径守卫、deny 正则锚定修正。v0.3 起白名单判定被模型取代，黑名单与 riskLevel 护栏以安全网形式保留（ADR-0008）。
- **ADR-0006：复合命令逐段全安全才放行**（机制被取代，2026-09-15）。先扫黑结构（`$(...)`、反引号、`eval`/`source`/`exec`、进程替换、heredoc、解码管道 → 直通），再用自带零依赖分词器按顶层 `&&`/`||`/`;`/`|` 引号感知切段，逐段过 deny 与白名单，一段不安全整条直通；重定向目标须在 cwd 内。理由：整串正则防不住 `safe && dangerous`（T3），而真正的 shell 解析器违背单文件零依赖（ADR-0002）。v0.3 起逐段白名单随 M2 白名单退出判定路径，黑结构交由模型语义判断；分词器保留，仅用于安全网的分段 deny 匹配。
